# SmithersBot Landing Page Creative Direction

## Purpose

These are creative instructions for the SmithersBot landing page used in the demo.

The README is the source of truth for product details. Do not restate the whole README here.

## Core line

Leave agents running without giving up control.

## Vibe

Smitherscore.

Almost cartoonishly professional. Obedient, precise, cheerful, and proficient.

The page should feel like SmithersBot prepared a formal presentation about itself with perfect manners and straight margins.

The humor comes from excessive competence, not jokes.

## Style reference

Use `launch-inputs/style-reference.html` as the composition reference.

Study it for:

- centered topbar
- small centered portrait
- serif wordmark
- large centered headline
- italic subhead
- single quiet button
- chapter intertitles
- Roman numerals
- exhibit-style screenshot framing
- thin borders
- generous vertical space
- `#f1e6cb` page background

Do not copy its fake Telegram content, fake goal, fake flowchart, or mock data.

Do not treat the HTML as final implementation.

Use it to understand the layout rhythm and visual restraint.

## Overall look

The page should be:

- centered
- formal
- spare
- warm
- polished
- highly ordered

It should not look like:

- generic AI SaaS
- a meme page
- a dashboard template
- a dark hacker tool
- a cluttered retro collage

## Background

Use the same page background color as the sample HTML:

`#f1e6cb`

Do not use dusty pink.

## Composition

Use one centered vertical spine.

Every major section should sit on the same axis.

Prefer stacking over side-by-side layouts.

Use generous empty space.

Use one main subject per section.

Nothing should be rotated, tilted, taped, stamped, scattered, or casually placed.

If two elements appear side by side, they must be balanced and symmetrical. Otherwise stack them.

## Hero

Use the provided portrait image in the hero.

The portrait should be small, centered, circular, and framed with a thin border.

Do not redraw the portrait.

Do not turn it into a large mascot.

Do not repeat it throughout the page.

Hero structure:

1. centered portrait
2. headline
3. short italic subhead
4. one primary action
5. optional secondary action if it stays quiet

Headline:

Leave agents running  
without giving up control.

Subhead direction:

An attentive operator for Claude Code and Codex.

## Page structure

Use a chapter-and-exhibit structure.

Suggested chapters:

- I. Plan
- II. Approve
- III. Run
- IV. Verify
- V. Demonstration
- VI. Setup

Each chapter should have:

- large Roman numeral
- one-word title
- one centered screenshot or asset
- one short italic caption

The chapter system is the main visual structure. Keep everything else restrained.

## Screenshots and assets

Use only real assets from `launch-inputs/`.

Expected inputs:

- `launch-inputs/assets/smithersbot-portrait.png`
- `launch-inputs/assets/smithersbot-jingle.mp3`
- `launch-inputs/screenshots/`

Do not generate fake flowcharts.

Do not generate fake screenshots.

Do not invent fake Telegram messages, fake goal IDs, fake terminal logs, or fake product data.

If a needed screenshot is missing, create a clean placeholder and list the missing asset in the final report.

Screenshots should be treated like exhibits:

- centered
- framed in a clean rectangular mat
- surrounded by breathing room
- followed by one italic caption

Do not crop screenshots too tightly.

Do not place screenshots beside long text.

## Typography

Use one dignified serif and one plain sans.

Serif should carry:

- wordmark
- headline
- subhead
- chapter numerals
- captions
- buttons

Sans should be used only where necessary:

- UI labels
- screenshot framing
- small technical details
- footer

Avoid:

- novelty fonts
- decorative caps
- loud font mixing
- all caps
- excessive bolding

Use sentence case.

## Color

Use a small palette based on the portrait and sample HTML.

Required page background:

`#f1e6cb`

Good colors:

- ink navy or near-black for text
- forest green from the jacket
- purple from the bowtie, used sparingly
- mustard yellow, used very sparingly
- warm off-white for exhibit mats

Avoid:

- gradients
- glass effects
- neon
- generic AI blue/purple glow
- heavy purple surfaces
- dark hacker theme

## Copy

Keep copy short, formal, and confident.

The copy should explain the product, not the joke.

Good lines:

- The plan is the contract.
- Claude Code drafts. Codex reviews. You decide.
- One worker per task. One gate it cannot fake.
- Ask before you act. Ask while you are stuck.
- Prepared, reviewed, approved, executed.
- Right away.

Avoid:

- flavor copy that exists only to be cute
- “Bureau” language
- “Est. 2026”
- “by appointment”
- “your AI butler”
- overexplaining the brand
- overemphasizing OpenClaw or fork history

## Jingle

The jingle belongs in the demo section and video preview.

Do not autoplay audio.

The landing page can include a subtle play button or video placeholder, but the page itself should not become a music page.

The jingle should feel like the opening cue to a formal product demonstration.

## Navigation

Keep navigation minimal.

Four links maximum.

Suggested links:

- Procedure
- Safety
- Setup
- Source

No sticky nav unless it is extremely restrained.

## Footer

Keep footer simple.

Mention:

- GitHub
- MIT license
- attribution through NOTICE.md

Do not put fork history in the hero or main product story.

## Standard

The brand can be funny.

The execution must be immaculate.

Every margin matters.

Every line should earn its place.

If the page feels slightly under-designed at first glance, it is probably moving in the right direction.
